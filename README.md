# roblox
Generated by [Rojo](https://github.com/rojo-rbx/rojo) 7.7.0, rebuilt as a roguelike melee wave-defense game with Ghost of Tsushima-inspired sword combat.

## Getting Started
To build the place from scratch, use:

```bash
rojo build -o "roblox.rbxlx"
```

Next, open `roblox.rbxlx` in Roblox Studio and start the Rojo server:

```bash
rojo serve
```

For more help, check out [the Rojo documentation](https://rojo.space/docs).

## Controls

| Action | Input |
| --- | --- |
| Sword attack (3-hit stance combo) | Left Click / `R2` |
| Parry (tap), guard (hold) | `F` / `L2` |
| Directional dodge dash | `Q`, `Shift`, or `L1` + movement direction |
| Air jump (double jump) | Press Jump again while airborne - one per airtime |
| Options / keybinds | `O` mid-run, or `OPTIONS` on the title screen |

The air jump is part of every fighter's kit from wave one: jump, then jump again in mid-air for a second kick, marked by a shockwave and a puff of sparks at your feet. The *Air Step* perk stacks a third one on top.

Every one of those is rebindable, including the `Options` key itself: open the panel and click a bind chip (or anywhere on its row), then press the key you want. `RESTORE DEFAULTS` puts the shipped controls back. Rebinds are per-session.

Three attacks inside the `1.2s` combo window finish with the heavy finisher *Heaven's Fall*.

## Combat Systems

- **Telegraphed enemies.** Every swing shows a `1.0s` windup with an amber warning ring (`PARRY OR DODGE`). Unparryable "flash cuts" wind up fast and flash crimson (`DODGE!`) - a parry does nothing against them.
- **Parry.** Opens a `0.2s` window. A hit inside it is fully negated, the attacker is stunned for `1.5s`, and you get a `1.5s` counter window for double damage. Holding `F` past the window settles into a guard stance (65% damage reduction).
- **Dodge.** `1.0s` cooldown with `0.25s` of invincibility frames at the start of the dash; dodging is the only answer to unparryable attacks.
- **Poise.** Slashes chip enemy poise; at zero the enemy staggers and its windup is interrupted. Heavy finishers break most poise outright, and *Sunder* breaks it instantly.
- **Waves.** Each wave adds enemies, tightens spawn intervals, scales health/damage/speed and mixes in brutes and shinobi.
- **Boss waves.** Every second wave (`CombatConfig.Boss.EveryWaves`) is a single named boss - the *Oni Shogun* or the *Fossil Tyrant* - with several times a brute's health, near-immunity to knockback and a dedicated health bar. `BossState` raises the bar and announces the fight; the next boss is flagged a wave early in the intermission banner.
- **Perks.** Clearing a wave pauses spawning and deals three random cards; the next wave starts once every living player has picked (or after 30s).

## Animating a rig

Clips are optional, and this repo ships without any. Every attack and parry resolves through three
layers, in order:

1. An authored clip -- an id in `CombatConfig.Animations`, or an `Animation` instance on the rig.
2. Roblox's own **stock sword clips** (`CombatConfig.Animations.Stock`: `rbxassetid://507770238`
   for R15, `rbxassetid://129961376` for R6). They need no asset ownership and load for every
   account, so the fallback works on a freshly synced place with nothing authored.
3. The **procedural frame override**: the sword arm is driven onto its captured rest offset --
   `out` into the cut pose, `hold` through the hit, `back` to idle -- so the game animates even if
   no asset loads at all. Poses and timings live in `CombatConfig.Procedural`, and `Flip` there is
   the one-line mirror fix for a rig whose shoulder axes run the other way.

Both clip layers play at `AnimationPriority.Action4`, above everything the default `Animate`
script uses, and for the duration of an action the default idle/tool tracks are weighted to zero --
those tracks write the same joints, so without that the arm ends up halfway between idle and
attack. Their original weights are handed back the moment the action ends.

Poses are written to each joint's own offset -- `Motor6D.C0`, or `AnimationConstraint.Transform` on
the newer joint type -- and never to `Motor6D.Transform`, which the `Animate` script and every
playing track own and rewrite each frame. Interpolation and the re-assert both run in
`RunService.PreSimulation`, after the Animator has evaluated the frame, so the last write before
the frame is drawn is the script's.

Animation **asset ids only exist once a KeyframeSequence has been uploaded to Roblox**. The
Animation Editor (or Open Cloud, with an API key) does the uploading; nothing in this repo can do
it for you. What the repo *can* do is author the sequence and hand you the number, so
`RigAnimationPack` does everything up to the publish click.

Select your rig in Studio and run this in the command bar:

```lua
local pack = require(game.ReplicatedStorage.Shared.RigAnimationPack)
pack.install(workspace.Rig)   -- author + attach + print ids
pack.preview(workspace.Rig)   -- walk, run, slash, guard (play mode)
```

`install` bakes Walk, Run, Slash1, Slash2, Heavy, Guard and Parry out of the game's *own* tuned
numbers -- the same `CombatConfig.Procedural` beats and `SwingRig` folds `CombatController` drives
onto each joint's rest offset -- so a rig wearing the clips moves the way the game already moves. It
then:

1. registers each clip with `KeyframeSequenceProvider`, which makes it playable immediately,
2. attaches an `Animation` instance to the rig under its `CombatConfig.Animations.Aliases` name,
   so `Animations.track` picks it up with no config change, and
3. stores a copy under `ReplicatedStorage.AnimSaves.<rig>`.

Those registered ids are **session-scoped**. For a permanent `rbxassetid://`, publish the clip:
the authored sequences are kept under `ReplicatedStorage.AnimSaves.<rig>` so the Animation Editor
can open them for that rig, and publishing returns the id to paste into
`CombatConfig.Animations` -- the shared module then resolves that clip by id instead of by the
instance the pack attached.

A publish is not always necessary. For **R15** rigs `RigAnimationPack.STOCK` carries Roblox's own
clips, which never expire: `507777826` walk, `507767714` run, `522635514` sword slash, `522638767`
sword lunge. Pass `{ source = "stock" }` to attach those instead. R6 rigs get the stock walk/run
(`180426354`) only -- the R15 sword clips cannot drive R6 joints, which is exactly why the pack
bakes its own.

## Music, Bosses & Scenery

### Background music

`MusicManager.client.luau` crossfades one looping bed per game state: **Combat** while a wave is live,
**Intermission** between waves, and **Menu** while a title screen or options panel owns the cursor
(falls back to the intermission bed when its own id is blank). Ids live in one place:

```lua
CombatConfig.Music = {
	Enabled = true,
	Volume = 0.35,
	FadeIn = 1.6,
	FadeOut = 1.2,
	Combat = "rbxassetid://...",
	Intermission = "rbxassetid://...",
	Menu = "",
}
```

Audio assets have to be uploaded to Roblox like animation ids, so this repo ships the slots empty
and the manager simply stays silent (with one console line) until you paste ids in. Any id your
group or account can play works; the manager logs if one never loads.

### Boss waves

`CombatConfig.Boss` is the whole schedule and budget:

```lua
CombatConfig.Boss = {
	EveryWaves = 2,                                       -- waves 2, 4, 6, ... (0 disables)
	Archetypes = { "OniShogun", "FossilTyrant" },         -- rolled in order
	HealthMultiplier = 3,                                 -- on top of the wave curve
	DamageMultiplier = 1.15,
}
```

The bosses themselves are ordinary entries in `CombatConfig.Enemies`, so the whole hit pipeline
already understands them. `WaveManager` plans `enemyCount = 1`, `EnemyAI` spawns it and tags the
model `CB_Boss`, and `BossState` drives `BossUI`: `Incoming` -> the announcement, `Fight` -> the
live `health / maxHealth` bar, `Defeated` -> the bar drops. Add a third boss by adding an archetype
and appending its id to `Archetypes`.

### Scenery

`EnvironmentSetup` builds a `Scenery` model outside the palisade - a ground slab, giant tree ferns,
crumbling castles, smoking volcanoes and dinosaur silhouettes. Everything is anchored, and
`CanCollide`, `CanTouch` and `CanQuery` are all off, so the wave AI, the katana hitboxes and any
raycast look straight through it. Layout is deterministic (same skyline on every server) and every
knob lives in `EnvironmentSetup`'s `SETTINGS` table - set `SceneryEnabled = false` to drop it all.

> **Rojo file naming:** a plain `*.luau` file syncs as a *ModuleScript*, so files that must run carry the `*.server.luau` (Script) or `*.client.luau` (LocalScript) suffix. Modules such as `CombatConfig.luau` and `KatanaFactory.luau` intentionally stay plain.

The server is authoritative: clients only send intent (`Attack`, `Parry`, `Dodge`, `SelectPerk`) and every request is validated against server clocks before it touches the world. Client-visible state travels through the attributes documented at the top of `CombatConfig.luau`.
